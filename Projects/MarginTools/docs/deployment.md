# Запуск и восстановление

Исходники сайта находятся в `margintools/`. Все команды npm, Prisma и Compose выполнять из этой папки. Исключение: Docker-сборка использует корень общего репозитория как контекст и `margintools/infra/docker/Dockerfile`. Корневой `.dockerignore` исключает второй проект, секреты и пользовательские файлы. Внутри контейнера структура `/app` и постоянный `/data/private` не меняются.

Локальный запуск описан в README. Требуются Node.js 24+, npm, Docker Compose и свободные порты 3000 и 5433. Зависимости фиксируются package-lock.json; установка через npm ci.

Docker-образ: `docker build -f margintools/infra/docker/Dockerfile -t margintools .`. Сервер запускается с окружением владельца, DATABASE_URL указывает на доступную PostgreSQL, APP_URL на реальный HTTPS-адрес. Docker CMD автоматически выполняет миграции и seed перед запуском. Бот запускается из того же образа командой `npm run bot`, с тем же DATABASE_URL; его база должна быть заранее мигрирована запуском сайта или отдельной командой npm run db:migrate. Реальный платёжный адаптер пока отсутствует. В production тестовая оплата всегда отключена.

Для обычного production обязательно STORAGE_MODE=s3 и приватный бакет. Заполнить S3_ENDPOINT, S3_REGION, S3_BUCKET, S3_ACCESS_KEY_ID, S3_SECRET_ACCESS_KEY. Публичный доступ к бакету отключить. Для тестового Amvera предусмотрено явное исключение: STORAGE_MODE=local, ALLOW_LOCAL_STORAGE_IN_PRODUCTION=true и PRIVATE_STORAGE_DIR=/data/private. Требуются постоянный диск и защита STAGING_MODE. Точные настройки, переменные и проверки описаны в [инструкции Amvera](amvera.md). Для восстановления пароля MAIL_WEBHOOK_URL должен принимать POST с email и ссылкой сброса и реально доставлять письмо. Юридические тексты и реквизиты предоставляет владелец.

Docker CMD теперь выполняет проверку окружения и записи, prisma migrate deploy, идемпотентный seed и запуск HTTP на 0.0.0.0:3000. Секреты сессий не требуются: используются случайные токены с хешами в PostgreSQL. Для Amvera обязательны DATABASE_URL, APP_URL, настройки хранилища и STAGING_BASIC_AUTH_USER / STAGING_BASIC_AUTH_PASSWORD; полный список приведён в отдельной инструкции. NODE_ENV=production и PORT=3000 заданы в образе.

Администратор: сначала зарегистрировать обычный аккаунт, указать его email в ADMIN_EMAIL и выполнить `npm run db:seed`. Не устанавливать эту переменную на чужой адрес.

Резервная копия локальной базы:
```sh
docker compose -f infra/docker/compose.yml exec -T postgres pg_dump -U margintools -Fc margintools > backup.dump
```
Хранить копию вне машины приложения, вместе с резервной копией приватного бакета. Перед восстановлением остановить сайт и бот и сохранить текущую базу. Восстановление в пустую базу:
```sh
docker compose -f infra/docker/compose.yml exec -T postgres pg_restore -U margintools -d margintools --no-owner < backup.dump
```
Затем проверить миграции, регистрацию, чтение сделки и действительность ссылок. В production настроить ежедневные копии и регулярно проверять восстановление. Политика обязательного хранения платежей зависит от выбранной юрисдикции и должна быть определена до реального эквайринга.

Локальная проверка 14.10.2026: pg_dump восстановлен через pg_restore в отдельную пустую базу, проверено чтение аккаунтов, КП и двух миграций. Перед публичным запуском нужна проверка восстановления приватного бакета.

Docker-образ собран и проверен локально 14.10.2026: установка зависимостей с нуля, генерация Prisma, production-сборка, миграции внутри контейнера и HTTP-ответ сервера. Образ включает OpenSSL и корневые сертификаты. В текущем окружении хранилище BuildKit сообщало об отсутствующих слоях; проверочная сборка выполнена командой `DOCKER_BUILDKIT=0 docker build -f margintools/infra/docker/Dockerfile -t margintools:local-verify .`.

Ничего не опубликовано. Telegram-токен владельца настроен только в локальном игнорируемом окружении. ИИ, почта, S3 и реальные платежи не включены.
