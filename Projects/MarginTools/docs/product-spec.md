# ТЗ для Codex: MarginTools

## 1. Задача проекта

Разработать полноценный русскоязычный веб-сервис **MarginTools**.

Сервис помогает пользователю пройти весь рабочий сценарий:

**Рассчитать цену → собрать сделку → подготовить КП → отправить клиенту → сохранить результат.**

В состав проекта входят:

1. Публичный сайт с бесплатными калькуляторами.
2. Личный кабинет с сохранёнными расчётами.
3. Конструктор сделок и коммерческих предложений.
4. Платные тарифы и автоматическая выдача доступа.
5. Telegram-бот с ИИ-агентом продавцом.
6. Административная панель.
7. База знаний для пользователей и ИИ-агента.
8. Аналитика использования и воронки продаж.

**Цель:** создать продукт с самостоятельной регистрацией, оплатой и получением результата, требующий минимального ручного обслуживания.

## 2. Аудитория и позиционирование

Основная аудитория:

- менеджеры по продажам;
- поставщики оборудования;
- небольшие торговые компании;
- индивидуальные предприниматели;
- специалисты, регулярно рассчитывающие закупку, продажу и прибыль.

Главный текст на первом экране:

> **От закупочной цены до готового коммерческого предложения**
>
> Рассчитывайте маржу, собирайте сделки и создавайте аккуратные КП в одном сервисе.

Основная кнопка: **«Рассчитать сделку»**.

Вторичная кнопка: **«Открыть калькуляторы»**.

Не размещать вымышленные отзывы, логотипы клиентов, показатели популярности и обещания гарантированной прибыли.

## 3. Дизайн

### Направление

**Светлый деловой интерфейс финансового сервиса.** Акцент на понятных цифрах, таблицах и быстром вводе данных.

Основной рабочий интерфейс должен напоминать качественный инструмент для ежедневной работы.

### Визуальная система

| Элемент | Решение |
|---|---|
| Основной фон | Светлый серо-голубой `#F5F7FB` |
| Карточки | Белые `#FFFFFF` |
| Основной текст | Тёмный `#172033` |
| Вторичный текст | Серо-синий `#667085` |
| Основной акцент | Синий `#2563EB` |
| Положительные значения | Зелёный `#15803D` |
| Предупреждения | Янтарный `#B45309` |
| Ошибки и убыток | Красный `#DC2626` |
| Границы | `#E2E8F0` |
| Скругления | 10–14 px |
| Шрифт | Локально размещённый шрифт с кириллицей, например Inter |
| Числа | Табличные цифры для ровных столбцов |

### Правила интерфейса

- На широком экране форма расчёта слева, результат справа.
- Результат обновляется при изменении значений.
- В многострочной сделке используется таблица с закреплёнными заголовками.
- На мобильном устройстве позиции сделки доступны в виде карточек.
- Рядом с терминами «маржа», «наценка», «НДС» есть короткие пояснения.
- Цвет дополняется текстом и значками: прибыльность нельзя обозначать только цветом.
- Поля имеют постоянные подписи.
- У каждого действия есть состояния загрузки, успеха и ошибки.
- При ограничении тарифа показывается конкретное объяснение и доступное действие.
- Интерфейс и сообщения об ошибках — на русском языке.
- Доступность: управление клавиатурой, видимый фокус, достаточная контрастность.

Публичные страницы используют ту же визуальную систему. На главной — **реальный интерактивный пример калькулятора**, а не декоративное изображение интерфейса.

## 6. Логика калькуляторов

Все вычисления реализовать в общем модуле, используемом сайтом и ботом. ИИ не выполняет финансовую арифметику самостоятельно.

### Маржа

- Прибыль = продажа − закупка.
- Маржа = прибыль / продажа × 100%.
- При нулевой продаже процент маржи не определён — показать пояснение.

### Наценка

- Наценка = прибыль / закупка × 100%.
- При нулевой закупке процент наценки не определён.

### Цена продажи

Два режима:

- от желаемой маржи: `закупка / (1 − маржа / 100)`;
- от желаемой наценки: `закупка × (1 + наценка / 100)`.

Не допускать расчёт конечной цены от маржи 100% и выше при положительной закупке.

### НДС

Режимы:

- начислить НДС сверху;
- выделить НДС из суммы.

Ставка вводится пользователем. Доступные предустановки управляются настройками; не выдавать выбранную ставку за универсально применимую.

### Скидка

- новая цена;
- размер скидки;
- прибыль после скидки;
- маржа после скидки;
- максимально допустимая скидка при заданной минимальной прибыли.

### Безубыточность

Ввод:

- постоянные расходы;
- цена единицы;
- переменные расходы на единицу.

Если цена не покрывает переменные расходы, показать, что при заданных условиях конечная точка безубыточности отсутствует.

### Общие правила

- Денежные расчёты без ошибок двоичной арифметики.
- Поддержка запятой и точки в дробных числах.
- Поддержка вставки сумм с пробелами.
- Явная политика округления.
- Отрицательные значения допускаются только там, где имеют смысл.
- Нельзя называть торговую прибыль «чистой прибылью после всех налогов».
- Процентные показатели итоговой сделки рассчитываются от общих сумм, а не усреднением процентов строк.

- распределение общих расходов по выбранному правилу;

- сумма продажи;
- дополнительные расходы;
- прибыль;
- маржа;
- наценка;
- расшифровка НДС при применимости выбранного режима.

**Закупочные цены, прибыль и внутренние комментарии никогда не попадают в клиентское КП или публичную ссылку.**

Опубликованное КП хранится как отдельная версия: изменения исходной сделки не должны незаметно менять уже отправленный документ.

- быстрые действия;

**Клиенты:** название, контактное лицо, контакты, реквизиты и заметки.

На первом этапе — один владелец на рабочее пространство. Командный доступ оставить расширением, не рекламировать до реализации.

## 11. Telegram-бот с ИИ-продавцом

### Назначение

Бот помогает пользователю решить задачу, демонстрирует пользу продукта и предлагает подходящий тариф.

**Основной сценарий продажи:**

Пользователь описывает задачу → бот уточняет необходимое → выполняет доступный расчёт → объясняет результат → предлагает следующую полезную функцию → при необходимости предлагает тариф и оплату.

### Меню

- 🧮 Рассчитать
- 📄 Создать КП
- 💼 Мой кабинет
- 💳 Тарифы
- ❓ Помощь

Команды:

`/start`, `/calculate`, `/pricing`, `/account`, `/help`, `/stop`.

### Работа без привязки аккаунта

Бот умеет:

- объяснять возможности сервиса;
- считать маржу, наценку, НДС и скидку;
- показывать тарифы;
- отвечать по базе знаний;
- давать ссылку на сайт.

### Работа после привязки

Дополнительно:

- показывать текущий тариф;
- открывать свои последние сделки;
- создавать черновик сделки из структурированного запроса;
- отправлять готовое КП по явному запросу;
- показывать действительную персональную ссылку на оплату.

Привязка через одноразовый токен с коротким сроком действия. Telegram username не используется как доказательство владения аккаунтом.

### Пример диалога

**Пользователь:**  
«Закупка 80 тысяч, хочу маржу 20%.»

**Бот:**  
«Цена продажи — 100 000 ₽. Разница между продажей и закупкой — 20 000 ₽, маржа — 20%, наценка — 25%. Дополнительные расходы в расчёт не включены. Создать сделку с этими данными?»

Если пользователь хочет оформить документ, бот предлагает конструктор КП. Платный тариф предлагается при конкретной потребности или достижении лимита.

### Инструменты ИИ-агента

Агент получает доступ только к разрешённым серверным функциям:

- `calculate_margin`
- `calculate_markup`
- `calculate_vat`
- `calculate_discount`
- `get_public_plans`
- `search_knowledge_base`
- `get_my_subscription`
- `list_my_recent_deals`
- `create_my_deal_draft`
- `create_my_checkout_link`
- `create_support_request`

Авторизация проверяется сервером для каждого вызова. Агент не выбирает произвольного владельца данных.

### Ограничения агента

- Представляется ИИ-помощником MarginTools.
- Использует цены и возможности из базы продукта.
- Не придумывает скидки, акции и функции.
- Не меняет подписку и не подтверждает оплату самостоятельно.
- Не запрашивает данные банковской карты.
- Не выполняет произвольный код, SQL или запросы к внутренней инфраструктуре.
- Не раскрывает чужие расчёты и документы.
- Перед изменением существующей сделки показывает изменения и запрашивает подтверждение.
- При неизвестном ответе сообщает об этом и предлагает обращение в поддержку.
- Инструкции пользователя и загруженные тексты не могут менять правила доступа.

При недоступности ИИ меню, калькуляторы и тарифы продолжают работать.

### Уведомления

Предусмотреть:

- подтверждение оплаты;
- уведомление об окончании подписки;
- ответ поддержки;
- необязательные полезные сообщения по согласию пользователя.

Маркетинговые сообщения выключены по умолчанию. Отказ от них доступен в один шаг. Не реализовывать массовые сообщения посторонним пользователям.

- **Интерфейс:** Tailwind CSS и доступные компоненты.
- **База данных:** PostgreSQL.
- **ORM:** Prisma.
- **Telegram-бот:** отдельный Node.js/TypeScript-процесс.
- **Валидация:** общие схемы для API и интерфейса.
- **Расчёты:** библиотека десятичной арифметики.
- **Файлы:** приватное S3-совместимое хранилище.
- **Развёртывание:** Docker.
- **Тесты:** модульные проверки расчётов и браузерные сценарии.

Использовать совместимые стабильные версии на момент начала разработки и зафиксировать зависимости.

## 14. Оплата и доступ

Реализовать адаптер платёжного провайдера, чтобы его можно было заменить без переписывания подписок.

Порядок:

1. Сервер создаёт заказ.
2. Пользователь переходит на платёжную страницу.
3. Сервер получает проверенное уведомление провайдера.
4. Событие сохраняется и обрабатывается однократно.
5. Подписка активируется.
6. Пользователь получает подтверждение.

Возврат пользователя на страницу «Успешно» сам по себе не подтверждает оплату.

До выбора реального провайдера:

- сделать тестовый адаптер;
- полностью проверить покупку в тестовом окружении;
- не показывать тестовые платежи как настоящие.

Реальное подключение зависит от страны, статуса владельца и доступных способов приёма платежей. Недостающие реквизиты и юридические сведения не выдумывать.

## 17. Обязательные проверки

### Расчёты

- закупка 800 ₽, продажа 1 000 ₽ → прибыль 200 ₽, маржа 20%, наценка 25%;
- закупка 800 ₽, целевая маржа 20% → продажа 1 000 ₽;
- закупка 800 ₽, наценка 20% → продажа 960 ₽;
- корректное начисление и выделение НДС;
- нулевая закупка и продажа;
- скидка, приводящая к убытку;
- дробные количества;
- округление нескольких строк;
- разные ставки и режимы НДС.

### Сквозные сценарии

1. Гость рассчитывает цену и сохраняет результат после регистрации.
2. Пользователь создаёт сделку и КП.
3. PDF корректно отображает кириллицу.
4. Публичное КП не содержит закупки и прибыли.
5. Пользователь не видит данные другого аккаунта.
6. Повторный webhook не продлевает подписку дважды.
7. Неуспешная оплата не выдаёт доступ.
8. Telegram привязывается к правильному аккаунту.
9. Агент считает через общий модуль.
10. При отказе ИИ базовые функции бота работают.
11. Все основные действия доступны на телефоне.
12. Отозванная публичная ссылка перестаёт открываться.

## 19. Требования к работе Codex

**Начинай реализацию проекта по этому ТЗ.**

- Сначала проверь существующие файлы и инструкции репозитория.
- Запиши ТЗ и ключевые решения в `docs/`.
- Составь рабочий план и веди статус этапов.
- Реализуй функции последовательно, с проверкой законченных сценариев.
- Не ограничивайся макетом и декоративными кнопками.
- Не выдавай заглушки за работающие интеграции.
- Если действие ещё недоступно, объясни это в интерфейсе.
- Для внешних сервисов создай адаптеры и тестовый режим.
- Не выдумывай ключи, реквизиты, отзывы и юридические данные.
- Продолжай независимую работу, если отсутствующие ключи блокируют только интеграцию.
- После каждого этапа запускай подходящие проверки и исправляй найденные ошибки.
- Перед завершением проверь запуск по README на чистом окружении.
- Подготовь `.env.example`, миграции, демоданные и инструкцию развёртывания.
- Составь точный список: что работает, что проверено и что требует внешней настройки.
- Не публикуй сайт и не включай реальные платежи до отдельного указания владельца.

**Критерий готовности:** пользователь может рассчитать цену, зарегистрироваться, сохранить сделку, сформировать КП, открыть его по ссылке, приобрести доступ в тестовом режиме и воспользоваться Telegram-ботом. Администратор может управлять продуктом и видеть ошибки через административную панель.
