# Проверки

`npm test`: формулы маржи и наценки, цена продажи, нулевые знаменатели, НДС, убыточная скидка, безубыточность, дробные количества, округление и разные режимы НДС.

`npm run typecheck`: весь сайт, бот и общие пакеты. `npm run build`: сборка Next.js.

`npm run test:integration`: 10 проверок привязки Telegram, приватных инструментов, тарифных лимитов, PDF с Unicode, тестового ИИ-адаптера, учёта токенов, очереди уведомлений и удаления файлов выбранного пространства. Используется отдельная база margintools_verify (переопределяется INTEGRATION_DATABASE_URL); перед первым запуском создать её, применить миграции и выполнить seed.

`npm run test:e2e` при работающей локальной базе и сайте: сохранение гостевого расчёта после регистрации, сделка, КП, PDF, публичная ссылка, отсутствие внутренних полей, изоляция двух пользователей, запрет админки, тестовая оплата и повторная обработка, неуспешная оплата, XLSX, неизменность опубликованной версии и отзыв ссылки. Отдельно проверяются импорт TSV и отсутствие горизонтального переполнения на экранах 390 и 1440 px. Скриншоты сохраняются в test-results.

`tests/proposals.test.ts`: семь проверок общих форматов сумм и дат Europe/Moscow, трёх шаблонов A4, длинных таблиц и условий, повторения заголовков, клиентских полей и отсутствия внутренних данных. Для двух проверок извлечения текста нужен `pdftotext` из необязательного пакета `poppler-utils`; без него эти проверки пропускаются. Для визуальной сверки использовать `pdftoppm -png -r 96 proposal.pdf preview` и сравнить с предпросмотром того же снимка данных. Poppler не нужен серверу: PDF создаёт pdf-lib с локальными кириллическими шрифтами.

Перед публичным запуском необходимы проверки с реальными тестовыми аккаунтами Telegram, выбранным ИИ-провайдером, почтой, S3 и платёжным провайдером. Визуальная сверка всех трёх PDF-шаблонов, многостраничной таблицы и длинных условий входит в приёмку документов, в том числе после обновления Amvera.

Браузерные проверки также подтверждают серверный запрет отключённого шаблона и удаление аккаунта только после проверки пароля. Сквозные проверки можно направить на отдельный сайт через TEST_BASE_URL; DATABASE_URL должен указывать на ту же базу, что и сайт, поскольку тест администратора назначает роль непосредственно в проверочной базе.
